# 運用マニュアル（社長・採用担当向け）

## 0. 最初の準備（1回だけ）

採用担当の Mac で行います（ターミナルを使います）。

1. このリポジトリを Mac に置く（GitHub Desktop で `yonezawa11n/Liful` を Clone、または「Code」→「Download ZIP」）
2. ターミナルでそのフォルダへ移動し、動作確認:
   ```
   python3 -m recruit demo
   ```
   `output/demo/dashboard.html` をダブルクリック → サンプルのダッシュボードが開けばOK
3. 本番データのフォルダを作る:
   ```
   python3 -m recruit init
   ```
   `private/` フォルダができます（Git には入りません。本人しか開けない設定になります）
4. 操作者名を設定（操作ログに残る名前）: `export RECRUIT_OPERATOR=採用担当` を `~/.zshrc` に1行追加
5. Mac の「FileVault」（ディスクの暗号化）がオンになっていることを確認（システム設定 → プライバシーとセキュリティ）

> 応募者データの保存場所を Google ドライブなどにする場合は、`RECRUIT_DATA_DIR=保存先フォルダ` を設定します（場所は社長と決める。SYSTEM_ARCHITECTURE.md §4）。

## 1. 毎日（採用担当・5〜10分）

1. 採用係長の管理画面（社長から共有された方法で）・公式LINE・電話で新しい応募を確認
2. 新しい応募を登録:
   ```
   python3 -m recruit add --name "氏名" --job HK-01 --source Indeed --date 2026-11-05
   ```
   - `--job` は求人ID（HK-01〜03・HD-01〜03・GH-01〜03）。`python3 -m recruit jobs` で一覧
   - 電話番号・メール・住所は**登録しない**（採用係長などで見る）
3. 今日やることを確認:
   ```
   python3 -m recruit tasks
   ```
   「初回連絡が遅れている」があれば最優先で連絡（目安: 応募から24時間以内）
4. 連絡・面接の結果に合わせてステータスを更新:
   ```
   python3 -m recruit status A0001 連絡済み --note "電話。面接希望"
   python3 -m recruit status A0001 面接予定 --date 2026-11-10
   python3 -m recruit status A0001 面接実施済み
   python3 -m recruit status A0001 内定          ← 社長・事業責任者が決めてから
   python3 -m recruit status A0001 内定承諾
   python3 -m recruit status A0001 入社予定 --date 2026-12-01
   python3 -m recruit status A0001 入社済み --date 2026-12-01
   python3 -m recruit status A0001 辞退 --note "他社に決定"
   ```
5. 次にいつ何をするかを書いておく:
   ```
   python3 -m recruit update A0001 次回対応日=2026-11-08 "次回対応内容=面接日の再提案"
   ```

### 選考ステータス（12段階）
応募受付 → 初回連絡待ち → 連絡済み → 面接日程調整中 → 面接予定 → 面接実施済み → 内定 → 内定承諾 → 入社予定 → 入社済み ／ 不採用 ／ 辞退

- 変更はすべて履歴に残ります（いつ・誰が・何から何へ）。
- 不採用・辞退・入社済みから戻すときは `--force`（履歴に残る）。
- **合否はツールでは決めません。** 社長・事業責任者が決めた結果を記録します。

### 申し送り欄に書いてよいこと・いけないこと
- 書いてよい: 業務上必要な事実（例: 普通免許あり、土曜は勤務不可、面接は町田事務所希望）
- 書いてはいけない: 健康状態・病歴・家族構成・妊娠・宗教・支持政党・出身地など（ツールが保存を止めます）

## 2. 毎週月曜（採用担当・20分）

1. 先週の媒体の数字を記録（社長に採用係長の管理画面の数字を教えてもらう）:
   ```
   python3 -m recruit media --week 2026-11-09 --media Indeed --job HK-01 --impressions 820 --clicks 31 --cost 0
   ```
2. 週次レポートを作る:
   ```
   python3 -m recruit report
   ```
   `output/reports/weekly_YYYY-MM-DD.md`（と .csv / .xlsx）ができます。氏名は入りません
3. ダッシュボードを更新: `python3 -m recruit dashboard` → `output/dashboard.html` を開く
4. 改善案を確認: `python3 -m recruit diagnose`
5. レポートを社長に共有（Markdown の中身を貼る、または Excel を渡す）
6. バックアップ: `python3 -m recruit backup`。月1回は `private/` を暗号化した外付けドライブなどにもコピー

## 3. 求人の公開・変更（社長）

1. 採用担当が `python3 -m recruit jobs` で「公開準備: 公開可」になったことを確認
2. 採用担当が `docs/採用係長_公開チェックリスト.md` を使って社長に公開を依頼し、記録:
   `python3 -m recruit publish HK-01 公開依頼中`
3. 社長が採用係長で公開
4. 採用担当が**ログアウトした状態**（シークレットウィンドウ）で Indeed などを検索し、求人が表示されることを確認してから記録:
   ```
   python3 -m recruit publish HK-01 公開確認済み --method "シークレットウィンドウでIndeed「訪問介護 町田市」検索し表示を確認"
   ```
   管理画面で「公開中」になっているだけでは「公開確認済み」にしません。
5. 求人の内容を変えたら `data/master/jobs.json` の `improvement_log` に「日付・変更内容・理由」を追記

**社長の承認が必要なこと**: 求人の公開・変更・停止／有料広告の開始・予算変更／内定・採否／応募者への正式な通知

## 4. 求人条件を確定させる（採用担当）

1. `python3 -m recruit checklist` → `docs/確認事項リスト.md` を印刷または共有し、事業責任者に確認
2. 確認できた項目は `data/master/jobs.json` で `["要確認", ...]` → `["確定", "確定した内容", "確認者・日付"]` に書き換え
3. 原稿（`jobs/drafts/`）の【要確認：…】を確定した内容に置き換え
4. `python3 -m recruit jobs -v` で残りを確認

## 5. 採用係長などから CSV を取り込む（使える場合）

1. 出力した CSV の1行目（列名）を見て、`data/import_mapping.example.json` をコピーして列名を書き換える
2. まず下見（保存しない）:
   ```
   python3 -m recruit import 応募者.csv --mapping data/import_mapping.saiyo.json --source 採用係長 --dry-run
   ```
3. 「重複（追加しない）」「エラー」を確認してから本番取込（`--dry-run` を外す）。取込前に自動でバックアップされます
4. 取り込んだ CSV ファイルは `private/` か削除（デスクトップ等に残さない）

## 6. 困ったとき

| 状況 | 対応 |
|---|---|
| 間違えて登録・削除した | `python3 -m recruit restore` で一覧 → `python3 -m recruit restore <フォルダ名>` |
| データがおかしい気がする | `python3 -m recruit validate`（重複・日付・センシティブ情報をチェック） |
| 誰がいつ何をしたか知りたい | `private/audit.log` |
| 目標人数を変えたい | `data/master/settings.json` を編集し、PROJECT_PLAN.md の変更履歴に書く |
| Excel が作られない | `pip3 install openpyxl`（Markdown と CSV は作られています） |

## 7. やってはいけないこと
- 応募者の CSV・氏名入りのダッシュボード（`--show-names`）を、メール・チャット・Claude などに貼り付けない
- `private/` を GitHub に上げない（.gitignore で防いでいますが、フォルダを移動したときは注意）
- 採用係長のパスワードをファイルやチャットに書かない
- 確定していない給与・勤務時間を求人に書かない
